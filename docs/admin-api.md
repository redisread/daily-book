# 管理 API 安全与限流

管理 API 使用 `CONTENT_API_KEY` Bearer 鉴权，所有响应均为 `Cache-Control: no-store` 且按 Authorization 区分缓存。认证失败返回 401，不执行限流写入；缺少服务端密钥时返回 503。

## 共享限流

认证成功后，D1 按固定逻辑身份 `content-api` 计数。密钥轮换和客户端 IP 不改变身份或额度。UTC 自然分钟从 `00` 秒开始，读写分别计数：

| 方法 | 每分钟上限 |
| --- | ---: |
| `GET`、`HEAD` | 120 |
| 其他管理方法 | 30 |

幂等重放、路由拒绝和已认证的参数/内容校验失败都会占额度。超限返回 429 `RATE_LIMITED`，`Retry-After` 指向下一分钟（秒，最少 1），响应不缓存。限流 D1 不可用时管理请求失败关闭并返回 503；公开读取不依赖此桶。限流计数在业务操作之前独立提交，因此后续业务失败仍占额度，但不会创建业务修改、成功审计或回执。未认证请求不计入本限流；密钥猜测防护需由部署边缘规则另行覆盖，本应用桶不声称提供此保护。

计数通过 D1 原子 upsert 跨 Worker isolate 共享，桶表只保留近几分钟的窗口记录。速率上限为服务端常量，不接受请求参数、客户端身份、客户端时钟或测试覆盖。

## 本地验证

```sh
npm --prefix apps/reader run verify:limits
```

验证器只使用本地隔离 D1 `00000000-0000-4000-8000-000000000072`，覆盖读写阈值、独立桶、并发竞争、UTC 分钟切换、密钥轮换、存储故障关闭和公开读取可用性。测试数据库在 `apps/reader/.cloudflare/management-state`；不连接远程 D1，不部署，不运行导入。

生产上线前需在 Cloudflare 边缘设置中单独审查并验证未认证猜密钥防护。限流实现本身不代表已应用该边缘规则，也不授予部署或生产数据导入权限。
