## Follow-up decision

- The `minimatch` moderate advisory remains only in the root ESLint/type-lint development graph. In this commit, `npm run lint` resolves to the fixed `eslint src` command and the workflow supplies no glob/path argument. PR content and config remain untrusted: CI has `contents: read` only, no production secrets, and no Cloudflare commands in CI/release preflight jobs. This is a time-bounded development-tool risk, not a permanent production waiver: review before first production enablement and sooner if an upstream compatible patch appears. npm proposes a breaking ESLint 10 → 9.39.5 change when forced, so it was not forced in this release-engineering slice.
- The root compatible lock refresh includes transitive major updates under current parent ranges (including `devalue` 5→6 and `undici` 7→8). They are subject to the complete local regression and independent review; any behavioral regression means revert that lock refresh and handle the dependency family separately.
- The fresh-install build found `js-yaml` was imported by application source but only type declarations were listed. It is now a direct runtime dependency at 4.3.2, which is outside all current advisory ranges; the added dependency was included in the post-fix audits and build.
- Reader's five findings are cleared by the 0.7.5 patch override. Keep this override only if clean-install, build, and full dev/built behavior all pass.
- Neither audit report is a live Cloudflare assessment. No production account, D1, Worker, secret, route or deployed bundle was inspected.
- CI quality/security/E2E jobs have 30-minute limits; Reader integration and manual release-preflight jobs have 60-minute limits. Reader jobs explicitly install Chrome and system dependencies because the verification scripts request Playwright `channel: 'chrome'`.
